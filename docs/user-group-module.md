# 用户与小组模块说明

更新时间：2026-07-23 19:00:00 +08:00

本文是 `用户（包含小组管理）` 模块的总说明，覆盖当前页面结构、权限规则、接口约定、文件边界和验证记录。模块实现尽量独立在用户、小组相关目录内，避免影响监控、工作区、视频分析和算法模块。

## 1. 模块边界

负责范围：

- 当前用户资料、头像、密码、模型 API 配置。
- 普通用户只读搜索。
- 管理员/超级管理员用户管理。
- 小组创建、邀请、成员查看、成员移除、退出小组。
- “我的”页和“小组”页的用户体验、信息架构和视觉排版。

不负责范围：

- 监控设备、直播、录像、切片。
- 工作区、问答记录、模型推理。
- 人脸识别、目标检测、算法训练或推理流程。

## 2. 当前页面结构

### 2.1 我的

首页顶部展示当前用户头像、姓名、工号、身份和手机号，并提供“更换头像”入口。功能入口按常见设置页结构分为三组：

- 账户：个人信息、账号安全、我的消息。
- 小组：新建小组、用户管理或用户搜索。
- 系统：模型 API。

底部保留“退出登录”，采用轻量危险样式，避免抢占主要功能入口。

### 2.2 我的消息

消息页包含固定页头、消息统计、刷新、清空消息和可滚动消息列表。

- 收到的邀请：展示待处理入组邀请，可同意或拒绝。
- 发出的邀请：展示自己作为组长发出的邀请状态。
- 清空消息：只清空当前页面视图，不删除后端邀请关系；点击刷新可重新拉取。
- 消息较多时只滚动列表区域，返回、刷新、清空入口不会被挤走。

### 2.3 个人信息

个人信息页只保留必要表单项：

- 姓名。
- 手机号。
- 头像更换。

头像从手机相册选择，不再要求用户手动输入头像地址。

### 2.4 账号安全

账号安全页独立修改当前用户密码，和个人资料编辑分离。

### 2.5 用户搜索

普通用户看到“用户搜索”，只支持查询基础资料，不提供管理操作。

可查看字段：

- 头像。
- 工号。
- 姓名。
- 手机号。
- 身份。
- 账号状态。

### 2.6 用户管理

管理员和超级管理员看到“用户管理”。

管理员可执行：

- 查询所有用户。
- 创建用户。
- 查看用户详情。
- 初始化用户密码。
- 删除用户。

超级管理员额外可执行：

- 将普通用户设为管理员。
- 将管理员设回普通用户。

限制：

- 管理员不能操作超级管理员。
- 管理员和超级管理员都不能在用户管理中操作自己的账号。
- 删除用户是物理删除，不是停用账号。

### 2.7 新建小组

所有用户都可以创建小组，创建者自动成为组长。

### 2.8 小组

小组页展示当前小组信息、成员列表和成员详情弹层。

所有正式成员可查看同组正式成员基础信息：

- 头像。
- 工号。
- 姓名。
- 手机号。

组长额外可执行：

- 修改小组名称。
- 邀请成员。
- 查看待确认邀请。
- 撤回待确认邀请。
- 移除成员。

邀请成员时输入工号、姓名或手机号，会即时显示候选用户头像、工号和姓名。

非组长成员可主动退出小组。组长不能直接退出自己创建的小组，避免小组无人管理。

## 3. 界面设计原则

本轮界面采用浅灰白背景、白色卡片、1px 细边框和少量蓝色重点操作，整体接近常见移动端设置页。

调整重点：

- 减少说明型副标题，保留真实数据、必要标题和标准操作文案。
- 统一卡片圆角为 8px 左右，避免过重的装饰感。
- 搜索、表单、弹窗、成员列表统一细边框样式。
- 普通操作使用轻按钮，主要提交按钮才使用蓝色实底。
- 删除、退出等危险操作保留红色，但减少大面积红色填充。
- “我的”和“小组”两个用户相关页面保持同一套视觉语言。
- 用户与小组页优先使用 HarmonyOS `sys.symbol` 系统符号表达返回、查看、搜索、刷新、保存、删除等操作，减少不必要的文字按钮。

## 4. 权限模型

### 4.1 角色

| 角色 | 说明 |
| --- | --- |
| `super_admin` | 超级管理员，服务初始化时创建，默认工号 `admin`，默认密码 `admin`。 |
| `admin` | 管理员，可查询、创建、删除用户，可初始化密码。 |
| `user` | 普通用户，可维护个人资料、搜索用户、创建小组、参与小组。 |

### 4.2 用户管理权限

| 操作 | 普通用户 | 管理员 | 超级管理员 |
| --- | --- | --- | --- |
| 修改本人资料 | 可以 | 可以 | 可以 |
| 修改本人密码 | 可以 | 可以 | 可以 |
| 只读搜索用户 | 可以 | 可以 | 可以 |
| 查询所有用户 | 不可以 | 可以 | 可以 |
| 创建用户 | 不可以 | 可以 | 可以 |
| 初始化密码 | 不可以 | 可以 | 可以 |
| 删除用户 | 不可以 | 可以 | 可以 |
| 设置管理员 | 不可以 | 不可以 | 可以 |

保护规则：

- 管理员不能操作超级管理员。
- 管理员/超级管理员不能删除自己。
- 管理员/超级管理员不能初始化自己的密码。
- 用户详情中密码只展示“已设置（不可查看）”，不展示明文密码。

### 4.3 小组权限

| 操作 | 非成员 | 普通成员 | 组长 |
| --- | --- | --- | --- |
| 查看小组成员 | 不可以 | 可以 | 可以 |
| 查看待确认邀请 | 不可以 | 不可以 | 可以 |
| 邀请成员 | 不可以 | 不可以 | 可以 |
| 撤回邀请 | 不可以 | 不可以 | 可以 |
| 移除成员 | 不可以 | 不可以 | 可以 |
| 修改组名 | 不可以 | 不可以 | 可以 |
| 退出小组 | 不可以 | 可以 | 不可以 |

## 5. 主要接口

接口沿用项目统一响应格式：

```json
{
  "code": 0,
  "message": "ok",
  "data": {}
}
```

### 5.1 用户接口

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/users/me` | 登录用户 | 获取当前用户。 |
| `PUT` | `/api/users/me` | 登录用户 | 修改当前用户资料、头像、密码或模型 API 配置。 |
| `GET` | `/api/users/search?keyword=xxx` | 登录用户 | 只读搜索用户基础资料。 |
| `GET` | `/api/users/?keyword=xxx` | 管理员/超级管理员 | 查询所有用户。 |
| `POST` | `/api/users/` | 管理员/超级管理员 | 创建用户。 |
| `GET` | `/api/users/<emp_id>` | 本人、管理员、超级管理员、同组成员 | 查看用户详情。 |
| `PUT` | `/api/users/<emp_id>/password` | 管理员/超级管理员 | 初始化用户密码。 |
| `DELETE` | `/api/users/<emp_id>` | 管理员/超级管理员 | 物理删除用户。 |
| `PUT` | `/api/users/<emp_id>/role` | 超级管理员 | 设置管理员或普通用户。 |
| `PUT` | `/api/users/<emp_id>/status` | 管理员/超级管理员 | 保留接口，当前前端不再作为主要操作。 |

创建用户请求：

```json
{
  "emp_id": "u001",
  "name": "张三",
  "phone": "13800000000",
  "password": "pass1234"
}
```

修改本人资料请求可按需传入字段：

```json
{
  "name": "张三",
  "phone": "13800000000",
  "avatar": "file://media/Photo/1/IMG.jpg",
  "password": "new-password",
  "llm_api_key": "sk-xxx",
  "llm_base_url": "https://example.com/v1",
  "llm_model": "qwen-plus"
}
```

初始化密码请求：

```json
{
  "password": "newpass123"
}
```

设置角色请求：

```json
{
  "role": "admin"
}
```

### 5.2 小组接口

| 方法 | 路径 | 权限 | 用途 |
| --- | --- | --- | --- |
| `GET` | `/api/groups/` | 登录用户 | 获取当前用户已加入的小组。 |
| `POST` | `/api/groups/` | 登录用户 | 创建小组。 |
| `GET` | `/api/groups/<group_id>` | 正式成员 | 获取小组详情。 |
| `PUT` | `/api/groups/<group_id>` | 组长 | 修改小组名称。 |
| `POST` | `/api/groups/<group_id>/invite` | 组长 | 邀请用户入组。 |
| `GET` | `/api/groups/invites` | 登录用户 | 获取收到的待处理邀请。 |
| `POST` | `/api/groups/<group_id>/respond` | 被邀请用户 | 同意或拒绝邀请。 |
| `GET` | `/api/groups/<group_id>/members` | 正式成员 | 获取正式成员列表。 |
| `GET` | `/api/groups/<group_id>/members?include_pending=1` | 组长 | 获取正式成员和待确认邀请。 |
| `DELETE` | `/api/groups/<group_id>/members/<emp_id>` | 组长 | 移除成员或撤回邀请。 |
| `POST` | `/api/groups/<group_id>/leave` | 非组长成员 | 退出小组。 |

创建小组请求：

```json
{
  "name": "小区A组"
}
```

邀请成员请求：

```json
{
  "emp_id": "u001"
}
```

处理邀请请求：

```json
{
  "action": "accept"
}
```

## 6. 返回结构

普通用户搜索返回基础字段，不返回 API Key 等私密配置：

```json
{
  "emp_id": "u001",
  "name": "张三",
  "phone": "13800000000",
  "avatar": "",
  "role": "user",
  "is_active": true
}
```

小组成员列表保留顶层字段，便于 ArkTS 前端直接渲染，同时包含 `user` 子对象，方便后续规范化：

```json
{
  "emp_id": "u001",
  "name": "张三",
  "phone": "13800000000",
  "avatar": "",
  "role": "user",
  "status": "accepted",
  "is_creator": false,
  "user": {
    "emp_id": "u001",
    "name": "张三",
    "phone": "13800000000",
    "avatar": "",
    "role": "user"
  }
}
```

## 8. 对接注意

- 前端接口路径均使用相对路径，例如 `/users/me`、`/groups/`，由 `HttpUtil` 统一拼接基础地址。
- 头像当前保存相册选择得到的 URI，不要求用户手动输入 URL。
- 删除用户会转移其创建的小组、工作区和问答记录归属，避免破坏其他模块数据。
- `GroupMember.status="pending"` 只表示邀请待确认，不应被监控、工作区等模块当作正式成员。
- 普通小组成员只看到正式成员，组长通过 `include_pending=1` 才能看到待确认邀请。
